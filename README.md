# Golden Time Router

환자 관찰 내용을 입력하고 주변 응급의료기관을 지도와 카드로 비교하는 4:3 태블릿 화면입니다. 검색 직전에 기기의 현재 위치를 다시 요청합니다. 첫 화면에는 받은 좌표, 확인 시각, 기기 정확도를 보여 주므로 지도 중심이 실제 위치와 일치하는지 확인할 수 있습니다.

## 실행

Node.js 22.12 이상에서:

```sh
npm ci
npm run dev
```

`http://127.0.0.1:5173/`을 엽니다. `.env.example`을 `.env.local`로 복사해 필요한 키를 설정합니다. `.env.local`은 커밋하지 않습니다.

| 설정 | 용도 |
| --- | --- |
| `VITE_DATA_MODE=server` | 서버에서 수집한 공개 병원 스냅샷 + 자동차 ETA. 환자별 추천 모델은 아직 연결되지 않음 |
| `VITE_DATA_MODE=demo` | 실제 병원명·좌표·공개 연락처에 시연용 시간·확률을 입힌 데모 |
| `VITE_DATA_MODE=live` | 완성된 추천 API 계약을 사용하는 모드 |
| `VITE_KAKAO_MAP_APP_KEY` | 카카오 지도를 표시하는 JavaScript 키. 로컬·배포 도메인 등록 필요 |
| `KAKAO_REST_API_KEY` | 서버 측 카카오모빌리티 자동차 ETA 조회 |
| `GROQ_API_KEY` | 서버 측 환자 서술 추출; 미설정 시 대체 제공자 설정 사용 |
| `VITE_API_BASE_URL`, `API_PROXY_TARGET` | 완성된 추천 API 연결에 사용 |

서버용 키에는 `VITE_`를 붙이지 않습니다. 키가 없으면 데모는 좌표 개요를 보여 주지만 실제 지도 타일은 표시할 수 없습니다.

## 데이터와 화면

- `server` 모드의 후보는 `public/server-catalog.json`의 NEMC 기관 ID·이름·좌표·연락처를 사용합니다. 지도 이름과 카드·전화 카드의 기관은 같은 ID를 가리킵니다. HIRA의 시설·장비·전문의는 보유 등록 정보로, NEMC 자원값은 수집 시각이 있는 관측으로 구분해 상세 화면에 표시합니다.
- `demo` 모드도 동일한 실제 기관 목록에서 출발지 주변 후보를 고릅니다. 환자 사례, 순위, 이동 시간, 수용 확률, 필요 자원 충족 표시는 **시연 값**이며 실제 수용 가능성이나 치료 적합성을 뜻하지 않습니다. 데모 연락처는 공개 기관 연락처를 보여 줍니다.
- 현재 지도 점은 브라우저가 제공한 좌표입니다. GPS 오차는 기기·권한·실내 환경에 따라 달라집니다. 좌표와 정확도를 먼저 확인하고, 병원 찾기를 누르면 새 위치를 받은 뒤 요청합니다. 다른 병원을 선택하면 출발지와 해당 병원이 함께 보이도록 지도를 맞춥니다.
- `server` 스냅샷은 실시간 피드가 아닙니다. 수용 확률이 없으면 0%로 바꾸지 않고 `정보 없음`으로 표시합니다. 관측 시간이 오래된 값은 현재 가용성으로 단정하지 않습니다.

서버 데이터 감사 결과와 모델 연결 조건은 [API_CONNECTIONS.md](API_CONNECTIONS.md)에 정리했습니다. 원시 NEDIS 행·비공개 서버 접속 정보·API 키는 이 저장소의 공개 화면 데이터에 포함하지 않습니다.

## 검증과 배포

```sh
npm run build
npm test
npm run test:e2e
```

Vercel의 앱 루트가 이 폴더라면 Vite 프로젝트로 배포하고 환경변수를 등록합니다. 이 프로젝트를 다른 저장소의 `golden-time-router` 하위 폴더로 복사한다면 Root Directory를 `golden-time-router`로 지정합니다. `vercel.json`과 `api/service.ts`가 추출·길찾기 서버 함수를 제공합니다. 배포 도메인은 카카오 JavaScript SDK 허용 도메인에도 추가해야 합니다.
